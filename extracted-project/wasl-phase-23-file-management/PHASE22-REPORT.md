# Wasl — Phase 22: Storage Center & Media Optimization

## Implemented
- Added authenticated `GET /api/account/storage` endpoint reporting attachment bytes/count, avatar bytes, total use, configured quota and remaining capacity.
- Added `attachments.getUsageForUser` to JSON and PostgreSQL storage adapters.
- Added per-account attachment quota enforcement before metadata persistence, with a clear HTTP 413 response and stable error code.
- Added a Storage settings panel with usage meter, remaining space, file count and refresh action.
- Added client-side avatar resize/compression (maximum dimension 512 px, JPEG quality 84%) before upload, while preserving server-side MIME/signature validation.
- Added `ACCOUNT_STORAGE_QUOTA_MB` configuration to environment examples and README documentation.
- Bumped package version to 0.20.0.

## Important limitations
- Quota check is read-then-write and is not atomic across simultaneous uploads or multiple application replicas. Do not use as a strict billing boundary until quota reservations are transactionally enforced.
- Local storage is counted from repository metadata plus avatar file size. Manually deleted files and unreferenced/orphaned files are not automatically reconciled; no destructive cleanup job was added.
- HTTP/PostgreSQL integration execution depends on installed Node dependencies and a disposable PostgreSQL database. Do not interpret static contract tests as live database validation.
